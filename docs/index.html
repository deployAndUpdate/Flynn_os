Flynn OS

Experimental bare-metal x86_64 kernel written in Rust. Serial-first OS with preemptive kernel threads, priority scheduling, and block/wake I/O.

Current phase: Kernel threads + preemptive scheduler + block/wake. User processes (Ring 3) planned for Phase 5+.

Quick Start

Flynn OS runs inside QEMU. Build the workspace and launch the BIOS image:

# Build kernel + disk images
cargo build

# Run in QEMU (serial → stdout)
cargo run

# UEFI boot (requires OVMF firmware)
cargo run -- uefi

Expected output: memory map, frame allocator stats, heap init, interrupt setup, ASCII banner, then alternating worker output and shell prompt > .

Pass criteria

  1. Memory map printed at boot
  2. Workers alternate: A:0 … B:done
  3. Shell prompt responsive
  4. help, ticks, sleep 50 → woke up

Architecture Overview

Flynn OS has two layers: a host runner (std Rust) that builds and launches QEMU, and a no_std kernel that runs on bare metal. Click each layer to expand details.

Host Layer (std Rust) ▼
Cargo workspace root. build.rs compiles the kernel binary and packages it into bios.img / uefi.img. src/main.rs launches qemu-system-x86_64 with -serial stdio — all kernel output goes to your terminal.
↓
Bootloader (rust-osdev 0.11) ▼
BIOS or UEFI boot loads the kernel ELF. Passes BootInfo: memory map, physical memory offset, optional GOP framebuffer. Sets up long mode and jumps to kernel_main.
↓
Kernel (no_std, x86_64-unknown-none) ▼
Core subsystems: memory (paging, heap, frames), interrupts (IDT, PIC, PIT, keyboard), task scheduler (preempt, priority, block/wake), serial driver, shell REPL. Minimal framebuffer marker as graphics PoC.

Data flow

Keyboard: PS/2 IRQ → ISR enqueues scancode → SPSC queue → input_loop task → terminal line editor → shell command on Enter

Timer: PIT ~100 Hz → timer ISR increments ticks → on_timer_tick() → preempt flag / wake blocked tasks / aging

Output: All logging and shell I/O via COM1 serial port (0x3F8), forwarded by QEMU to host stdout

Memory Layout

Frame Allocator

Bitmap allocator over the largest usable RAM region (up to 128 MiB / 32768 frames). Boot self-test runs 64 allocate/free cycles. Task stacks use mapped frames — not heap allocation.

Component Module
Bitmap frame allocatormemory/frame_allocator.rs
Page table mappingmemory/paging.rs
Heap (linked_list_allocator)memory/heap.rs
Mapped task stacksmemory/stack.rs

Interrupts & Drivers

8259 PIC remapped (IRQ0=32 timer, IRQ1=33 keyboard). PIT configured for ~100 Hz. IDT loaded, then sti enables interrupts.

IRQ Source Handler action
IRQ 0 PIT Timer Increment ticks, notify scheduler (preempt, wake, aging)
IRQ 1 PS/2 Keyboard Read scancode, enqueue to SPSC queue, wake keyboard waiter

Serial Driver

COM1 at port 0x3F8, 38400 baud. Logger, shell, and all user-facing output go through serial. QEMU maps this to host stdout via -serial stdio.

Task Scheduler

Preemptive scheduler with 4 priority levels (0=idle, 3=highest). Timer sets preempt flag; tasks check at safe points. Click a state to learn more.

Parameters

Parameter Value Meaning
QUANTUM_TICKS 2 Time slice (~20 ms at 100 Hz)
AGING_TICKS 15 Ready tasks boost priority after this many ticks
MAX_PRIORITY 4 Priority levels 0..3

Boot tasks

Task Priority Role
worker_a1Demo: prints A:0..4, sleeps, exits
worker_b1Demo: prints B:0..4, sleeps, exits

idle0hlt + preempt check when nothing runs

Context switch

Assembly switch_task saves/restores RSP only. Stack initialized via init_context with a synthetic return to task entry. Phase 2.1 will add true ISR context switch via iretq from timer ISR.
